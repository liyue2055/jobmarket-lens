## Team ownership

The coordinator owns shared contracts, integration, final validation and Git/release operations.
Delegate bounded tasks with exact writable paths and acceptance evidence. The agent lanes are:

1. V2 data: upstream import, isolated source storage, merge/provenance, sanitized release export (WP01–WP02).
2. V2 frontend: worker/query engine and Explore/Compare/Skills/Evidence, sharing and accessibility (WP03–WP09); release preparation WP10.
3. V3 research: source/rights/quality evaluation design and synthetic design specifications only.

Agents share the workspace. Do not edit another agent's assigned paths or undo unrelated changes.
Shared schema changes require coordinator agreement before consumers implement them. One agent owns
any shared file at a time. Use isolated branches/worktrees for implementation when concurrent changes
would overlap; report branch and base commit to the coordinator. Do not cherry-pick between worktrees
without the coordinator. Subagents do not commit, push or deploy unless assigned those operations.

## Luna groundwork routing

Use `gpt-6-luna` for bounded work with explicit inputs, writable paths and objective checks. Spawn
with `fork_turns="none"` and provide the repository, relevant instructions and self-contained task;
use medium reasoning by default. Do not send broad repository context or private evidence unnecessarily.

Suitable tasks include file inventories, local documentation-link/JSON checks, formatting, mechanical
renames, source-register consistency and small isolated edits after a lead has fixed the specification.
Any fixture generation must follow a lead-defined expected result and remain clearly synthetic.

The lead retains architecture, shared contracts, merge/provenance rules, analytical formulas,
privacy/publication decisions, provider rights interpretation and release approval. Luna may check
conformance to an agreed rule but does not decide those rules. Tests or reports generated by Luna are
not independent proof that its own implementation is correct; the lead reviews outcomes.

Give one deliverable and a short checklist per assignment. Begin read-only when the task is uncertain.
Require observed results and file paths, not a claim of completion alone. If requirements conflict or
scope grows, Luna reports the uncertainty to the coordinator; the coordinator narrows the task or
assigns it to a lead. Subagents do not autonomously create a delegation tree.

There are four concurrent agent slots including the coordinator. Reserve one worker slot for Luna
when useful; run V3 research intermittently or pause an idle lane rather than exceeding capacity.
Keep the existing data, frontend and V3 handoffs as ownership boundaries.

Private descriptions, SQLite/raw evidence, API credentials and restricted people records must remain
outside Git and public build artifacts. Preserve the local public-field allowlist. Imported upstream
values retain their source/date basis and do not become locally observed evidence. Never infer closure
from an upstream absence, hires from closed postings, or available talent from an employed profile.

V2 must build without the private DB. Validate actual imported scale, source modes, stable cohort IDs,
unknown values, privacy sentinels, exports, accessibility and deployment behavior. Do not claim planned
commands/tests exist or passed. Run relevant checks and report failures and limits accurately. No
application tests are needed for documentation-only coordination changes; validate JSON and links.
